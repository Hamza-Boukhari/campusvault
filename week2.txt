1. Which PID does node have inside the container? Which PID does the host see? Why two numbers?

Inside the container, the Node.js process usually has PID 1. On the host, the same process has a different PID, such as 2456. This happens because Docker uses PID namespaces. A process can have different PIDs in different PID namespaces.

2. Which Linux distribution is inside? Is it the same as your laptop's?

The container uses Alpine Linux, as specified by the base image node:22-alpine. It may be different from my laptop's Linux distribution. Containers share the host's kernel but can use a different user-space distribution.

3. In B7, which layer is the biggest? Why?

The biggest layer is usually the one created by RUN yarn install --production, because it installs the Node.js dependencies and their required packages. The exact largest layer depends on the output of docker history getting-started.

4. After the one-word change, did yarn install run again? Why is that a waste of time, and which line order would avoid it?

Yes, yarn install ran again because COPY . . appears before RUN yarn install --production. Changing a source file invalidates the COPY layer and the following layers.

This wastes time because the dependencies have not changed. To avoid this, copy package.json and yarn.lock first, install dependencies, and then copy the application source code. This allows Docker to reuse the dependency installation layer when only source files change.
